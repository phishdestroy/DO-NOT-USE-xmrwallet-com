How the Captcha Works

The system has three components designed to prove human interaction:

  1. Proof-of-Work (PoW) — a computational puzzle the browser must solve
  2. Slider Puzzle — drag a red dot to a dark circle on a PNG image
  3. Trajectory Tracking — the browser records mouse movement coordinates and timestamps during the drag

Step 1: The Proof-of-Work

When authentication fails (error codes 75–80), the client fetches /captcha_api.php, which returns a JSON payload:

{
  "status": "success",
  "image":  "data:image/png;base64,iVBORw0KGgo...",
  "pow_c":  834729,
  "pow_t":  291047,
  "pow_prime": 999983,
  "start_x": 150,
  "start_y": 75
}

The client must find a nonce such that:

(nonce * nonce + pow_c) % pow_prime == pow_t

This is their "mining function" from the JavaScript source:

// Mining function — from xmrwallet captcha JS
function minePoW(pow_c, pow_t, pow_prime) {
    for (let nonce = 0; nonce <= 5000000; nonce++) {
        if ((nonce * nonce + pow_c) % pow_prime === pow_t) {
            return nonce;
        }
    }
    return null;
}
Defeated: It's a simple quadratic brute-force over at most 5 million integers. A Python loop solves it in ~0.1 seconds. No GPU needed. No complexity. This "proof of work" provides essentially zero protection.

Step 2: The Slider Puzzle

The captcha image is a PNG with a noise background and a small dark circle somewhere in the image. The user must drag a red dot from a starting position to the center of the dark circle.

The server validates:

  • final_x, final_y — where the user dropped the dot
  • trajectory — JSON array of {x, y, t} mouse positions with timestamps
  • pow_nonce — the solved PoW value
Defeated: The dark circle is trivially detectable with basic image analysis. Convert the PNG to grayscale, scan for clusters of pixels below a darkness threshold, compute the centroid. 15 lines of Python with Pillow. The noise background provides no meaningful camouflage — the target circle is always significantly darker than the surrounding pattern. 
# Find the dark circle — the entire "AI" needed
img = Image.open(BytesIO(b64decode(data))).convert("L")

target_x = sum(p[0] for p in dark) / len(dark)

Step 3: The Trajectory

The captcha tracks mouse movement during the drag and sends it as a JSON array:

[
  {"x": 150, "y": 75, "t": 1709312847100},
  {"x": 152, "y": 74, "t": 1709312847105},
  {"x": 158, "y": 73, "t": 1709312847112},
  ... 40-60 more points ...
  {"x": 243, "y": 108, "t": 1709312847450}
]

This is meant to verify that a human physically dragged their mouse. The server presumably checks for straight-line robotic movement.

Defeated: Generate synthetic trajectory with an ease-out curve (mimicking natural mouse deceleration), add Gaussian noise for human-like wobble, and space timestamps 3–8ms apart. 20 lines of Python produces trajectories indistinguishable from real mouse input. The server's validation is too weak to differentiate. 
# Synthetic trajectory with human-like motion
for i in range(num_points):
    progress = i / (num_points - 1)
    eased = 1 - (1 - progress) ** 2    # ease-out curve

    x = start_x + (end_x - start_x) * eased
    y = start_y + (end_y - start_y) * eased
    x += random.gauss(0, 1.5)      # horizontal wobble
    y += random.gauss(0, 1.0)      # vertical wobble

    t += random.randint(3, 8)      # 3-8ms between points

The Complete Flow — From Trigger to Bypass

The captcha is not loaded on every page visit. It triggers only after an authentication attempt fails with specific error codes (75–80). The normal flow for a real user:

  1. User submits login form → POST /auth.php
  2. Server responds with 0:75 through 0:80 (captcha required)
  3. Client fetches GET /captcha_api.php (returns image + PoW params)
  4. Browser mines PoW in a loop (up to 5M iterations)
  5. User drags red dot to dark circle while browser records trajectory
  6. Client resubmits POST /auth.php with captcha fields added:
    • final_x, final_y — drop position
    • trajectory — JSON mouse path
    • pow_nonce — solved PoW value
  7. Server validates and returns session

Our automated bypass follows the same flow: detect error code, fetch captcha, brute-force PoW (0.1s), analyze image (pixel scan), generate synthetic trajectory, resubmit. The entire captcha is solved programmatically in under 2 seconds per attempt. 100% success rate.

Why This Captcha Failed

Every component of this captcha has a fundamental weakness:

Component Intended Defense Why It Failed
Proof-of-Work Computational cost 5M iterations is trivial. Solves in 0.1s on a single CPU core. Would need 1012+ iterations to matter.
Slider Puzzle Visual recognition Dark circle on noise background is trivially detectable with basic pixel thresholding. No distortion, no decoys, no color variation.
Trajectory Tracking Human behavior verification No ML-based analysis on server side. Simple synthetic curves with Gaussian noise pass validation. The server likely only checks that the array is non-empty and endpoints match.
Custom Implementation Obscurity Client-side JavaScript is fully readable. The entire algorithm is exposed in the page source. Security through obscurity is not security.

The captcha was built by someone who understands web development but not adversarial machine learning or anti-bot systems. A real captcha service (reCAPTCHA, hCaptcha, Cloudflare Turnstile) would have been significantly harder to bypass — but those services require domain verification and would expose the operator to takedown through the captcha provider. The operator can't use legitimate services because their operation is criminal.

async function minePoW() {
    if (!powParams) return;
    document.getElementById('pow-status').textContent =
        "Verifying cryptographic proof... (Generating CPU load)";
    submitBtn.disabled = true;

    // Yield to browser UI render before locking up CPU
    await new Promise(r => setTimeout(r, 50));

    const { pow_c, pow_t, pow_prime } = powParams;
    let nonce = 0;

    // Mining Loop: Find (nonce^2 + C) % Prime == T
    while (true) {
        // Because JavaScript numbers are double precision floats,
        // Number.MAX_SAFE_INTEGER easily supports this math.
        let calc = ((nonce * nonce) + pow_c) % pow_prime;
        if (calc === pow_t) {
            solvedNonce = nonce;
            break;
        }
        nonce++;

    document.getElementById('pow-status').textContent =
        "Security verified. Ready.";
